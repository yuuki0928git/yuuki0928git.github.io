# 会話ログ更新

Messenger / Instagram のエクスポートZIPまたは個別JSONを、既存の会話TXTへ追記する静的ツールです。ZIPの展開・照合・変換・圧縮はブラウザ内で実行します。通常版と完全統合版の両方に対応します。提供された仕様のうち、最新の共有・ノート・同時更新指示を優先しています。個別の人物やスレッドの設定は含みません。

## 起動

このディレクトリで `python3 -m http.server 4173 --bind 127.0.0.1` を実行し、`http://127.0.0.1:4173/` を開きます。Node.jsやビルドはサイトの実行に不要です。GitHub Pagesの配布先は `/meta-log/` を想定しています。`file://` ではES Modulesの制限があるためHTTPで開いてください。公開先は `https://yuuki0928git.github.io/meta-log/` です。

## 操作

1. 「既存ログのZIP・TXT（追記先）」へ最新版のログを選択します。新着入力とは別欄です。元ファイルは変更しません。
2. 「MetaエクスポートZIP（新着の入力元）」へZIPを丸ごと選択します。複数選択に対応し、写真・動画を手で削除する必要はありません。従来の個別JSON入力も使えます。
3. ZIPごとに自分側アカウントの識別名を指定します。同じプラットフォームの同じ自分側アカウントには毎回同じ識別名を使い、別アカウントや別プラットフォームには別名を使います。設定JSONの `accounts` は入力候補を表示するための情報です。
4. 手元の設定JSONを読み、「照合して確認」を押します。通常は設定に登録済みの会話・統合ソースだけを照合し、未登録はスキップします。参加者が同じでも、アカウントやスレッドが異なる会話を自動統合しません。
5. 必要な未登録会話だけ「未登録・アカウント確認の候補」を開き、「候補を開く」から既存TXTへ割り当てるか、新規名（`folder/sample_ver1.0.txt` など）を指定します。候補一覧には本文を表示せず、登録前のTXTも自動作成しません。
6. 完全統合版がある場合は連動設定を確認します。登録した1対1のソースだけを対象にし、グループDMは統合版へ入りません。通常版の新着に加え、登録済み別ソースだけの新着でも統合版を照合・更新します。通常版が新着更新の起点で統合版が保留になったときは、関連通常版も保留します。
7. 版・JST境界・追記件数・正規化件数・スキップ数・保留理由を確認し、チェック後にZIPを保存します。確認省略を選んでも、曖昧な入力は保留します。保留を除く出力には明示チェックが必要で、除外一覧もTXTとして出力します。
8. 設定JSONも書き出し、更新済みZIPとセットで手元に保存します。新設定には入力元アカウントとスレッドの組み合わせを記録します。本文は含みませんが、個別対応表・参加者名は私的情報です。公開しないでください。

対応するZIP構造、読み込み上限、旧設定の移行手順は [ZIP_INPUT.md](ZIP_INPUT.md) に記載しています。

Safariではダウンロードのほか、生成後の「ZIPを保存・共有」リンクを使えます。OSの共有ダイアログを自動で開く機能はありません。iPad実機のファイルピッカー、複数選択、Blob保存・Filesへの保存、バックグラウンド復帰、大容量でのメモリ使用は未確認です。

## 設定JSON

`config.example.json` は空の例です。`schemaVersion` は2です。従来の1も読み込めます。個別JSONでアカウント指定を省略した場合は従来のスレッド識別方式を維持します。旧設定をZIP入力に使う場合、入力元アカウントの確認が必要です。

| フィールド   | 意味                                                                                                                                                                                                                                                                                                                               |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `accounts`   | `{ "id": "account-A", "label": "自分側アカウントA" }` の配列。手元の入力候補です。ZIPのファイル名から自動推定しません。                                                                                                                                                                                                            |
| `aliases`    | `{ "別表示名": "正規表示名" }`。照合用の別名。別アカウントを無条件に一括登録しないでください。                                                                                                                                                                                                                                     |
| `logs`       | `{ "path": "folder/sample_ver1.0.txt", "participants": ["合成A", "合成B"], "reactionFormat": "standalone" }` の配列。参加者の組み合わせから候補を表示します。`reactionFormat` は `standalone` または `inline`。未指定では既存TXTから判定します。`ordinaryShareWithContent` は通常共有のURLと本文の併記を指定する任意の真偽値です。 |
| `mappings`   | `{ "thread": "合成スレッド識別子", "path": "folder/sample_ver1.0.txt" }` の配列。利用者が確認済みの対応。ZIP由来は `thread` にアカウントと元スレッドを組み合わせたキーを記録し、`account` と `sourceThread` にも元情報を残します。画面で登録・書き出しできるため、このキーを手入力する必要はありません。                           |
| `integrated` | 完全統合版ごとの設定配列。形式は次項参照。                                                                                                                                                                                                                                                                                         |

上記は説明用の合成名です。実際の設定をGitHubへ追加しないでください。設定はブラウザの永続ストレージには保存しません。

### 完全統合版の設定

画面で設定でき、設定JSONへ書き出せます。次は説明用の合成例です。公開する設定例ファイル自体は空のままです。

```json
{
  "path": "folder/full_ver1.0.txt",
  "initialLabel": "IG(合成A)",
  "triggerThreads": ["synthetic/source-a"],
  "always": false,
  "sources": [
    {
      "thread": "synthetic/source-a",
      "label": "IG(合成A)",
      "rename": { "匿名の合成名": "合成A" },
      "compactBlankLines": true,
      "suppressOrdinaryShareWithContent": true
    },
    {
      "thread": "synthetic/source-b",
      "label": "IG(合成B)",
      "rename": {},
      "compactBlankLines": false,
      "suppressOrdinaryShareWithContent": false
    }
  ]
}
```

これを `integrated` 配列の要素として保存します。`path` は既存統合版のZIP内パス、`initialLabel` は先頭のソースです。元TXTの全ソースのラベルを登録し、今回JSONを選択しないソースも残します。`triggerThreads` は連動の起点になる通常ログのスレッドです。`always` がtrueなら通常版の新着がなくても統合版を照合します。今回の入力に登録済みの統合ソースがある場合も、新着を見落とさないよう統合版を照合します。通常版を作らないソースは会話の対応先で「完全統合版のみ」を選択できます。

先頭ラベル・置換・ソース別の空行整理と共有表記は既存統合版に合わせて設定してください。フォルダIDが変わった場合、画面のソース選択で新しいスレッドへ結び直します。匿名表示名や本文から同一人物を推測する機能はありません。同じ参加者の別グループも自動統合しません。

統合版は解析→再出力の完全一致を確認し、各ソースの元JSONを専用形式へ整形して既存イベントと内容込みで照合します。通常TXTの行は流用しません。未収録分は元のミリ秒を用いて途中にも挿入します。元TXTにしかない同秒の発言のミリ秒が不明なとき、内容・個数が矛盾するとき、同一ミリ秒の順序が決まらないときは保留します。過去の表記差を日時と送信者だけで同一視しません。

## 照合・保存仕様

- `thread_path` または `thread_id` で分割JSONをまとめます。ファイル名では判定しません。識別情報不足、参加者不一致、同一ミリ秒の順序が不明、末尾照合が一意でない入力は保留します。重複データを勝手に削除しません。
- 元のミリ秒で整列し、UTC+09:00（Asia/Tokyoの現行JST）へ変換します。TXTの末尾最大5件のJST日時・送信者・本文を照合します。時刻だけから推測しません。
- 本文の改行を維持します。本文中の行がTXTの日付・メッセージ構造と衝突する場合は保留します。UTF-8以外のTXT、未対応ヘッダーや不明なリアクション形式も安全に確定できなければ保留します。
- 更新のないファイル内容は元のバイト列のままZIPへ格納します。ZIPコンテナ自体の圧縮バイト列やメタデータの完全一致は保証しません。
- 追記時は `ver1.9 → ver2.0`。追記0件で版は上げません。既存システム行のReacted正規化だけの場合、同じ版を維持して正規化件数を表示します。
- ストーリーの共有はURLと本文を併記します。リンクなし共有は明示的に分かる投稿者または `[シェア]` と本文を残します。URLはリンク化・プレビューしません。
- 写真は `[写真 N枚]`、動画は `[動画 N件]`、音声は `[音声メッセージ]`、通常版のスタンプは `[スタンプ]`、通話本文は原文を保持します。通常版のリアクションは既存に合わせて独立した `Reacted 絵文字 to your message` または ` →絵文字(した人)` を使います。新規通常版は独立行です。時刻情報がない反応には対象メッセージの表示時刻を使います。統合版は常に行末形式、GIF URLは `[スタンプ]`、空スタンプは元の統合版仕様どおり空欄にします。本文のノート反応・返信も保持します。
- 10,000件の倍数と境界後6時間以上の空白を警告します。履歴の完全性を保証する判定ではありません。
- 既存ログZIP/TXTの入力合計と展開後の上限は256MiBです。Meta入力ZIPは全体を展開せず、JSON単体32MiB・JSON累計256MiB・一覧32MiB・最大10万エントリの上限で処理します。同期処理を含み、大容量では画面が一時停止したり、端末のメモリ制限で失敗する可能性があります。

## プライバシー

外部API・CDN・解析タグ・アップロード先はありません。ZIPライブラリfflate 0.8.2のブラウザ用ESMとMITライセンスを `vendor/` に同梱しています。CSPは `connect-src 'none'`、画像・フレーム・フォーム等も禁止し、スクリプト・CSSは同一サイトのものだけを許可します。本文やエラー詳細をコンソールへ出力しません。localStorage・sessionStorage・IndexedDB・Service Workerは利用しません。「選択・メモリを消去」で参照とBlob URLを破棄できます。OSやブラウザのメモリを物理的に消去する保証はありません。

GitHubへ含めるものはコード・説明書・合成テスト・空の設定例のみです。実データ・設定・ZIP・過去のメモ類を追加しないでください。

## 検証

開発用に `npm ci`、`npm test`、`npx playwright install chromium`、`npx playwright test --project=chromium` を実行します。WebKit検証は依存ライブラリを用意して `npx playwright install --with-deps webkit`、`npx playwright test --project=webkit --project=ipad-webkit` を実行します。`ipad-webkit` はiPad相当の画面・タッチ・モバイル設定によるエミュレーションです。配布済みvendorの更新は明示的に行い、バージョンとライセンスを揃えてください。

検証結果と未確認事項は [VALIDATION.md](VALIDATION.md) に記載しています。

## 読み込みエラー・古い表示が残る場合

画面下部の更新版表示で読み込んでいる版を確認できます。`https://yuuki0928git.github.io/meta-log/?v=20261110-zip3` は今回の更新版用URLです。画面・本体JS・依存JS・CSSのURLに同じ版を付け、前の版のファイルがブラウザに残っていても混ざらないようにしています。

`E_SOURCE_IN_DESTINATION` はMetaエクスポートZIPを追記先欄へ入れた場合、`E_CONFIG_JSON` / `E_CONFIG_VERSION` は設定ファイルの選択・形式、`E_EXISTING_PATH` は重複・不正なパス、`E_INPUT_SIZE` / `E_EXISTING_SIZE` はサイズ上限、`E_EXISTING_READ` は追記先ファイルの読み込み、`E_EXISTING_ZIP` はZIP展開の失敗です。iPadで `E_EXISTING_READ` が出る場合は、Filesでダウンロード済みのファイルを選び直してください。

問い合わせ時は版とエラーコードだけで初期診断できます。本文・会話名・アカウントIDや実ファイルを送る必要はありません。エラー表示へ生の例外文やJSON本文は含めません。今後の静的ファイル更新時は、HTMLと依存モジュールの版付きURLを一緒に更新してください。
