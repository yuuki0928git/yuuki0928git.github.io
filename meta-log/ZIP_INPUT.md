# MetaエクスポートZIP入力

## 対応する構造

会話JSONのファイル名 `message_1.json`、`message_2.json` … をZIPのファイル一覧から探します。ファイル名は分割分の発見だけに使用し、会話そのものは入力元アカウント・JSONのスレッド識別情報・フォルダ・参加者で確認します。

| 構造例（すべて合成）                                           | 対応                                             |
| -------------------------------------------------------------- | ------------------------------------------------ |
| `messages/inbox/sample/message_1.json`                         | 対応                                             |
| `your_instagram_activity/messages/inbox/sample/message_1.json` | 対応                                             |
| `your_facebook_activity/messages/inbox/sample/message_1.json`  | 対応                                             |
| `inbox/sample/message_1.json` と `message_2.json`              | 対応、同じアカウントの同じスレッドとして結合     |
| `messages/archived_threads/sample/message_1.json`              | 対応                                             |
| `messages/message_requests/sample/message_1.json`              | 対応                                             |
| `messages/filtered_threads/sample/message_1.json`              | 対応                                             |
| その他の外側フォルダの下の会話JSON                             | Meta形式を検証し、識別情報を確認できる場合に対応 |
| 写真・動画・音声・プロフィール等                               | 展開せず対象外                                   |
| HTML形式だけのエクスポート                                     | 非対応、JSON形式が必要                           |

`thread_path` があるときはメッセージフォルダとの一致を確認します。ない場合は `thread_id`、それもないZIPでは会話フォルダのパスを識別情報にします。個別JSONでは識別情報不足をファイル名だけで補わず保留します。日付・タイトルや参加者が同じという理由で別スレッドをまとめません。

自分側アカウントの識別名は利用者が明示します。ZIPの名前や相手の表示名から推測しません。別アカウント・別プラットフォームには別の識別名を使ってください。同じ識別名を割り当てた複数ZIPは、同じスレッド識別情報があるときだけ分割分をまとめます。重複する同一ミリ秒の順序が不明なときは、既存の変換ルールに従い保留します。

## 登録・スキップ・保留

- 通常更新するのは `mappings` または完全統合版の `sources` にアカウント付きで登録済みの会話です。
- 未登録はスキップします。TXTを自動作成しません。本文を画面・コンソールへ出しません。スキップしたJSON本文は一覧情報として保持しません。
- 候補一覧は参加者・スレッド・入力元・件数を表示し、50件ごとに切り替えます。必要な候補を明示的に開くと、そのJSONだけを再読み込みします。既存TXTへの割り当て・新規名の確認後、設定を書き出して登録できます。
- 同じメンバーの別グループも、スレッド識別情報で区別します。グループDMは通常のグループ用TXTへ更新でき、1対1の完全統合版には入りません。
- 登録先が複数、参加者やフォルダ識別情報が矛盾、分割JSONの一部が壊れている、JST末尾を一意に照合できない、同一ミリ秒の境界が不明、などは保留します。
- ZIP一覧自体を読めない入力がある場合、同じ入力元アカウントの関連入力も保留し、不完全な分割分だけで更新しません。
- 確認省略でもスキップ・保留は維持します。保留を除く場合だけ明示的な部分出力を行い、一覧を出力ZIPに含めます。未登録をスキップした件数は確認画面に表示します。

## 旧設定を使う場合

schemaVersion 1は読み込み可能です。従来の個別JSON入力では、アカウント欄を省略すれば元のスレッド識別方式を維持します。

アカウント情報がない旧設定をMeta ZIPへ使うときは、自動でアカウントを推測せず保留します。候補を開いて対象を確認し、通常ログの対応先を指定してください。完全統合版にも関係する会話は、連動設定内のソースを今回のアカウント付きスレッドへ結び直す必要があります。未確認の連動対象がある通常ログは保留します。

確認後の設定JSONを書き出すとschemaVersion 2になり、アカウント・元スレッド・更新後のファイル名を保存します。設定は自動的に端末内へ永続保存しません。

## ZIPを読む方法と上限

外部ライブラリを追加せず、同梱済みfflate 0.8.2をJSONのDEFLATE解凍に利用します。

1. `Blob.slice()` で終端と中央ディレクトリだけを読み、ファイル一覧を取得します。ZIP全体への `arrayBuffer()` は呼びません。コメント付きZIPなどでは終端探索に最大65,557バイト読む場合があります。
2. 該当する会話JSONの圧縮データ部分だけをスレッドごと・JSONごとに読みます。メディアは解凍しません。
3. ローカルヘッダー・圧縮方式・名前・展開サイズ・CRCを検証します。登録前の本文も外部へ送信しません。
4. 更新結果は従来のJST変換・境界照合・リアクション・共有・版上げ処理へ渡します。入力元のJSONやメディアを出力用ファイル一覧へ加えることはありません。

対応する圧縮方式はSTORE（非圧縮）とDEFLATEです。単一ディスクのZIP64、データディスクリプタ付きZIPにも対応します。暗号化された会話JSON、分割ディスクZIP、UTF-8以外の非ASCIIファイル名、対応外圧縮方式、破損した管理情報は理由を表示して保留します。対象外メディアの圧縮方式・CRCは確認しません。

上限は一覧32MiB・10万エントリ・会話JSON単体32MiB（圧縮時/展開後）・読み込みJSON累計256MiBです。候補の再読み込みも累計に含みます。入力元ZIP自体の大きさだけで一律に拒否しません。既存ログZIPは従来どおり全内容を維持するため、入力・展開後とも256MiBを上限とします。

ブラウザのメモリ不足やタブ終了は捕捉できない場合があります。ZIP64の4GiB超オフセットは仮想ファイルを使った合成テストで確認し、実際の巨大ZIPやiPad実機のメモリ上限は未確認です。

## 出力とプライバシー

出力ZIPには、既存ログの最新版一式と更新・新規登録したTXTを格納します。未更新の既存ファイル内容はバイト単位で維持します。入力元エクスポートのJSON・メディアは含みません。保留の部分出力では保留一覧TXTも含みます。

個別対応表・選択ファイル・本文はブラウザの永続ストレージへ保存せず、通信もしません。アカウント識別名やスレッドを含む設定JSONは利用者の手元で扱う私的情報です。GitHubへ含めるものはコード・説明書・空の設定例・合成テストだけです。
