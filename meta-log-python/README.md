# iPadで使うPythonチャット履歴更新ツール

InstagramのZIP/JSON・LINE履歴を既存TXTへ追記する、端末内処理のWebアプリです。変換の正解は利用者から受領した `reference_converter.py` です。元ファイルは変更せず、CPython 3.12.7（Pyodide 0.27.7）で呼び出します。FastAPIサーバーへチャットをアップロードする方式ではありません。

## 普段の操作

1. 「今までのログ」へ前回の最新版ZIP、または既存TXTを選ぶ。
2. 「新しいエクスポート」へInstagramのZIP/JSON、LINE履歴を選ぶ。複数選択可。
3. 「更新内容を確認」を押す。追記件数・末尾照合・新版・ストーリー補完・保留理由を確認する。
4. 「この内容で更新ZIPを保存」を押す。

ファイルをまとめてドラッグ＆ドロップすることもできます。種別は内容・形式から振り分けます。登録済みの対応表にない会話は自動作成せず、必要な会話だけ利用者が保存名を指定して再確認します。

## 初回だけ

「初回だけ：Claudeのファイルを選ぶ」を開き、受領した **reference_converter.py と仕様書.md** を選びます。仕様書の§4.1から私的な `mapping.json` を作ります。既に `mapping.json` があれば仕様書の代わりに選べます。

参照コードは次のSHA-256と一致する場合だけ実行します。

`2d2758ae67bd82879925c66856540a3bb858c315f5d6006f5b17c8bf8d4c34d6`

対応表と参照コードは更新ZIPの `mapping.json`、`__converter/reference_converter.py` に含めます。次回からはそのZIPを選べばよく、別の設定ファイルを毎回管理する必要はありません。これらは私的なファイルとして扱い、公開しないでください。受領した仕様書・個別対応表・元の参照コードはこの公開ソースには含めません。

## 変換と照合

- IGの順序は参照コードの `load_messages`：ファイル名の辞書順→全体反転→秒で安定ソート。ミリ秒で並べ直しません。
- 文字・マーカー・空行・リアクション・共有の出力は `render`、`append_to_log`、`build_new_log`、`parse_line_txt`、`merge_sources` に委譲します。
- 通常TXTは `append_to_log` を呼び、末尾不一致なら書きません。利用者がその会話の続行を明示して再確認した場合だけ進めます。
- 複数ソースの既存ログへの追記は、参照コードの `merge_sources` に境界用の一時イベントを渡し、そのイベントだけを取り除いて既存テキストへ接続します。変換文字列を別ロジックで作り直しません。
- 通常版と同時更新先は、両方の照合・件数を確認してからまとめて採用します。一方が不一致なら両方を保留します。
- ファイル名の比較はNFC。新旧の文字列・本文は勝手に正規化しません。
- 追記0・補完0の既存ファイルは元のバイト列を維持します。追記0なら版も上げません。ストーリー補完のみは同じ版のまま補完結果を保存します。
- 未登録・曖昧なアカウント・対応表の重複・読み込めない会話JSONは警告し、推測で書きません。

## 上限とZIP構造

Meta ZIPは **5GiB以下**。`messages/inbox/<folder>/message_N.json`、`your_instagram_activity/messages/inbox/<folder>/message_N.json` に対応します。ZIP64・STORE・DEFLATEを扱い、一覧と必要な会話JSONだけを `Blob.slice()` で読みます。写真・動画は展開しません。未登録のフォルダは本文を読まず一覧化します。

一覧32MiB・10万エントリ、JSON単体32MiB、処理する既存ログとJSON/LINEの合計256MiBが目安の保護上限です。ZIPの大半が画像・動画なら、ZIP全体をメモリへ取り込む必要はありません。ただし実際の5GB ZIPとiPad実機のメモリ限界は未検証です。

## プライバシーと削除

- 実行時は同じ配布物のプログラムだけを読み込み、CDN・外部API・解析タグを使いません。
- 入力を読む前にPythonを準備し、その後はWorkerの `fetch` を禁止します。チャットを送るHTTPエンドポイントもありません。
- 一時JSONはPythonのメモリ上の仮想ファイルシステムへ置き、参照コードで読んだ直後にTemporaryDirectoryで削除します。
- ZIP生成後にセッションを空にし、Workerを終了して入力参照を解放し、ファイル選択欄も消去します。ダウンロード用Blob URLは5分で、または消去・ページ終了時に破棄します。
- localStorage / sessionStorage / IndexedDB / Service Workerに入力や本文を書きません。本文や生の例外をログに出しません。共有URLを自動で開きません。
- `blob:` の読み込みは端末内のファイル操作であり、外部通信ではありません。検証ではHTTP(S)通信の宛先・メソッド・本文の有無を分けて確認します。

## 参照コードで見つかった制限

LINEの引用符で囲まれた本文が、さらに引用符で終わる一部の形（例：閉じが連続3個）では、参照コードが次のメッセージまで取り込む場合があります。**参照コードは変更していません**。外側でレコード数を検査し、この形は警告して保留します。修正には利用者への相談が必要です。

また、受領した仕様書のシステム文正規化などの記述と参照コードの挙動が異なる場合は、指示どおり参照コードを優先します。過去行の時刻逆転・後から付いたリアクションを推測で直しません。

## 開発・検証

配布物は `web/` の静的ファイルです。`python3 -m http.server 4180 --directory web` でローカル確認できます。iPadで使う配布先はHTTPSが必要です。静的ホストではPyodideの約14MBのプログラムも同梱します。

Pythonテストは受領した参照コードをプロジェクトの `reference_converter.py` に置いて実行します。このファイルはgitignore対象です。

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/pytest -q --disable-warnings
npm ci
npx playwright install --with-deps chromium webkit
npm run test:browser
node --test tests/zip-reader.test.mjs
```

§9の実データそのものは提供されていないため、合成データで17件・89件/補完2件・IG51件＋LINE76件などを再現して検証します。実データの一致確認済みとは報告しません。
